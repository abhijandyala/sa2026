# Frontend requests for the Field Shift API

From Abhi (frontend) to Rahul (backend). The frontend builds against the draft examples in the backend branch (`docs/api/examples/`, Nov 12) and uses their field names unchanged. These are the additions the screens need. The saved sample in `web/public/data/sample/` already carries them in this shape, generated by `web/scripts/make-sample.mjs`, so you can see exactly what is expected.

Every item is optional for the UI: if a field is missing, the screen says "not available" instead of computing anything itself.

## 1. Per-year spring results for each planting window (needed for the years strip)

The strip shows all 45 springs at once, colored by dryness, and lets the grower replay any year. Calling `/v1/seasons/{year}/replay` 45 times is too slow, so `POST /v1/plans/compare` could return:

```json
"spring_windows": {
  "soy_full_season": {
    "id": "soy_full_season",
    "label": "30 days before full-season soybean planting",
    "plant": "05-12", "start": "04-12", "end": "05-11",
    "threshold": { "value": 61.2, "unit": "mm", "method": "bottom 20% …", "reference_span": "1981-2025", "status": "complete" },
    "median_mm": 88.0,
    "dry_count": 9, "denominator": 45,
    "shortcuts": { "typical": 1996, "dry": 2007, "wet": 2003 },
    "years": [
      { "year": 2007, "start": "2007-04-12", "end": "2007-05-11", "total_mm": 38.4, "status": "complete",
        "rank": 3, "of": 45, "percentile": 6.7, "is_dry": true,
        "gwettop_window_mean": 0.41, "gwetroot_window_mean": 0.48 }
    ],
    "eras": { "dry_spring": { "earlier": {…}, "recent": {…}, "diff_pp": 5.0, "result": "similar", "caveat": "…" } }
  },
  "soy_double_crop": { "…": "same shape, June window" }
}
```

and each plan carries `"spring_window_id": "soy_full_season"`.

## 2. Earlier vs recent for dry windows (no rule needed)

The no-cover and wheat plans have no rye check, so their cards show dry planting windows by period instead. That is `spring_windows.<id>.eras.dry_spring` above, using the same era rules as the checks (1981–2000 vs 2006–2025, at least 15 of 20).

## 3. Wheat double-crop plan

Cards show three plans: `no_cover`, `rye_12d` (with `rye_19d` as the earlier end date), and `wheat_double_crop`. Until the wheat catalog rows land, the sample marks the wheat plan `"status": "partial"`, keeps its June weather replay, and lists the timing check as `"verdict": "unknown"` with `"reason": "catalog_missing: …"`. The UI shows the reason without the code prefix.

## 4. Per-season winter rain (for the replay line, later phases)

`plans[].winter.per_season`: `[{ "year": 2007, "rain_mm_without_cover": 41.2, "status": "complete" }, …]`, so the strip can show the selected winter's value next to the median.

## 5. Per-date detail in the sensitivity sweep (needed for the rye slider)

As the grower drags the rye end date, the card, the 3D field and the year strip follow the chosen date. To mark "check this spring" and show earlier vs recent for any date without the UI applying the rule itself, each `points[]` entry could also carry:

```json
{ "terminate": "04-30", "gap_days": 12, "living_cover_days_planned": 211,
  "rain_mm_without_cover_median": 46.3, "checks_count": 9,
  "qualifying_years": [1986, 1988, …],
  "eras": { "earlier": {…}, "recent": {…}, "diff_pp": 5.0, "result": "similar", "caveat": "…" } }
```

Without them, the slider still shows counts, gaps and rain, and the per-year mark and the period split say "not available for this date".

## 6. Two-year presets

Still open: the cards describe two-year rotations, but the API evaluates one winter (corn → winter → soybean). The UI currently shows the first winter and lists the second winter as a gap. Tell us how the second winter (soybean → rye or clover → corn) will be represented.

## What the frontend relies on and will not recompute

- Totals, ranks, percentiles, dry labels, check counts, qualifying years, era counts and labels.
- `thresholds.*`, including the heavy-rain definition (shown as pending while `value` is null).
- `meta.draft`: when true, the UI shows a "Draft sample data" banner.

# API examples (generated)

These are **real responses** for the Union County sample, generated by `python -m fieldshift.api.contract` with the network disabled (`FIELDSHIFT_OFFLINE=1`; reads only the committed weather snapshot). They replace the hand-written drafts. Weather is real NASA POWER data; plan dates are the assumed sample dates in `data/samples/union_plans.json`; the heavy-rain definition is the published 3 in (76.2 mm) daily value with its source in `thresholds.heavy_rain.source`.

Only `meta.request_id` is replaced (`req_example`) so the files are stable. A test (`tests/api/test_api_contract.py`) validates each response against `docs/api/openapi.json` and fails if the committed files drift from the code. Regenerate with:

```bash
python -m fieldshift.api.contract
```

## Reading the responses

- Every response carries `meta = {plan_version, catalog_version, snapshot_hash, request_id}`. Ignore any response whose `request_id` is not your latest request's.
- Statuses use the fixed vocabulary: `complete | partial | unavailable | unknown | inapplicable | unsupported | invalid_input | manual_check | insufficient_data`.
- `thresholds` always comes back; never hard-code the heavy-rain value or the dry cutoff. `dry_spring` has one cutoff per planting window (keyed by planting MM-DD).
- A missing value is `null` with a status or reason next to it. A real 0 stays 0.
- Era blocks (`eras`) carry `{evaluable, events, pct}` per period, the shared `threshold_value`, a `result` label and a fixed descriptive caveat. `eras_shared_years` repeats them on the years every compared plan could be evaluated for.
- `data_sources` states where each input came from and its freshness: `fresh | cached(<time>) | snapshot | unavailable`.
- Plan and rotation IDs: see `../presets.md`. Edit a plan by sending the full `Plan` in `plans` with the same `plan_id`.

Field names differ from the old drafts in a few places; the list is in `docs/handoff.md` (2026-11-13).
